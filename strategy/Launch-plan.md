## Delivery sequence

Roles below are proposed responsibilities. Assign people and dates after repository and access review.

| Stage | Responsible role | Work and observable exit condition |
|---|---|---|
| 1. Establish baseline | Founder + site maintainer | Compare the handoff against the studio document and live routes. Identify hosting, domain control, existing content and working features. Record which items to retain. |
| 2. Verify access | Community lead + each product owner | Test the community invite as a newcomer. Demonstrate each product or record its limited availability. Approve exact copy and URLs. Unconfirmed products may retain informational briefs. |
| 3. Review journeys | Designer + maintainer | Ask a newcomer to find how to contribute and an NFT user to find a wallet eligibility brief. Observe where each hesitates. Repeat on a narrow phone and with keyboard navigation. Resolve unclear actions. |
| 4. Integrate and stage | Site maintainer | Port the approved design into the identified repository, preserve current routes or provide redirects, check all internal and external links, focus order, contrast, titles and mobile layout. Prepare a rollback to the preceding deployment. |
| 5. Publish directory | Founder + maintainer | Sign off the staging URL. Set production indexing intentionally, inspect share previews using the supplied banner and verify the domain after release. Confirm every published access link and owner. |
| 6. Run first feedback cycle | Community lead + studio owner | Collect recurring problems in the approved channel. Pick one, record the evidence and test one focused change. Report the decision and outcome to contributors. |

## Product release evidence

- **MintPulse:** Install in an approved test server, schedule a controlled reminder, verify time zone and delivery, and document permissions and recovery from a missed reminder.
- **DropCheck:** Demonstrate a supported OpenSea-hosted drop with multiple addresses and phases. Verify official data and authentication boundaries, test a failed lookup, compare report and CSV results, and inspect retention and logs before making a privacy claim. Check allocation, price and schedules against source values where available.
- **Strike:** Obtain the owner's exact supported flow and access model. Demonstrate intended behavior in a controlled environment, document user authorization, costs and failure outcomes, and establish support ownership before publishing access instructions.

## Ongoing ownership

Keep one row per product with owner, evidence, status, URL, last verification date and next review date. Site maintainer updates the directory whenever access changes. Community lead records recurring questions and whether people can find the correct brief or join path. During the first feedback cycle, review anonymized observations together and choose one improvement. Adding analytics or collecting wallet addresses is unnecessary for this review.
