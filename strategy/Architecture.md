# Guidepost Labs — Website Architecture

## Purpose

The website presents Guidepost Labs as a community-driven Web3 product studio. It is the public-facing studio layer, not a shared product dashboard. Strike, DropCheck and MintPulse retain distinct product scopes and release paths.

## Technology decisions

| Layer | Decision | Reason |
|---|---|---|
| Framework | Next.js 16 App Router | Server-rendered pages, static product routes, metadata and Vercel deployment |
| UI | React 19 + TypeScript strict mode | Typed, reusable components and centralized product records |
| Styling | Custom CSS | Preserve the supplied visual language without adding a component framework or utility dependency |
| Content | Typed records in `lib/site.ts` | A single source of truth for product status, descriptions and CTA destinations |
| Rendering | Static generation for current pages | No live server data is needed for the current studio website |
| Hosting | Vercel-ready | Matches the expected Next.js deployment workflow |
| Data layer | None | No account, wallet, membership or scan-history data is required by this site |

## Route map

- `/` — positioning, ecosystem summary, product discovery and community CTA.
- `/products` — directory of the three products.
- `/products/mintpulse` — MintPulse product brief and development status.
- `/products/dropcheck` — DropCheck product brief and pre-launch status.
- `/products/strike` — Strike product brief and restricted-access status.
- `/community` — official Discord entry point and contribution context.
- `/studio` — Guidepost Labs positioning and proposed community-to-product loop.
- `/robots.txt` and `/sitemap.xml` — generated by Next.js metadata routes.

## Content model

`lib/site.ts` owns the product list. Every product has a stable slug, category, short and long description, status, status detail, problem framing, documented scope, availability statement and CTA destination. The homepage, directory and detail routes consume these same records.

A new product status or access link should be changed in this file, not copied into multiple pages. Add a real product URL only after its owner has confirmed it and the link has been tested.

## Security and privacy posture

The studio website does not ask for wallet connections, private keys, email addresses or user accounts. It does not include a database or analytics integration. External Discord links open in a new tab with `rel="noreferrer"`.

This is separate from DropCheck's own privacy requirements. The website does not implement or certify DropCheck's wallet authentication, eligibility retrieval, session cleanup or private-key handling.

## Future extension boundaries

If a product later needs its own app, authentication or backend, it should be evaluated as a separate product architecture. Do not add shared wallet custody, shared login, database storage or cross-product dependencies to the studio site without a documented requirement.
